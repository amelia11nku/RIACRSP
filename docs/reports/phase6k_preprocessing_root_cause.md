## 诊断结论

历史前处理本身不是逐位确定的。同一进程、同一模型、同一份 GPU 输入，重复运行原 CUDA FP16 autocast 路径仍产生多个不同分数向量。图及候选张量两次重建完全一致，重复运行前后输入哈希也不变。因此，差异不能归结为候选身份错位或输入重建发生变化。

本次预先固定 5 个 R12 状态：上次完整原路径复核的两个派生特征失败状态，加 S/M/L 各一个按 ID 排序选择的对照。每个状态无插桩重复推理 30 次，再做 10 次模块输出指纹跟踪。5/5 个状态均出现分数变化，每个状态出现 2–4 个不同分数向量。部分重复恰好匹配存档，部分不匹配；没有从中挑选有利重复作为通过证据。

所有输入投影输出稳定。最早出现变化的阶段位于关系层或其后的图池化、目标集合编码。模块插桩会改变执行时序，所以其结果用于定位，不作为延迟或完全等价测试。

## 固定算子输入的直接证据

通过 `TorchDispatchMode` 在真实原模型中捕获 `aten.index_add_.default` 的目标初值、索引及源张量，保留其 dtype 和 shape。随后只重复该调用，每次使用相同输入副本，且验证捕获操作数未被修改。

5 个状态各捕获 171 次调用，共 855 次，每次分别在默认和确定性设置下重复 50 次：

| 调用位置 | 默认模式下观察到多个输出的调用数 |
| --- | ---: |
| `encoder.py:168`：关系消息累加 | 117 |
| `encoder.py:75`：segment softmax 分母累加 | 67 |
| `encoder.py:56`：segment mean 累加 | 25 |
| `action_encoder.py:61`：目标集合注意力累加 | 5 |
| 合计 | 214 / 855 |

这些 214 次不稳定归约的操作数均为 **FP32**，但位于历史 FP16 autocast 流水线中；不能将原因写成“FP16 原子累加”。开启 `torch.use_deterministic_algorithms(True)` 后，本次 50 次重复未再观察到变异。235/855 次调用的确定性结果与默认模式第一次数值不同，故直接切换确定性算法不是存档逐值等价修复。

以上结论由本地实际操作数实验支持；尚未逐条重建当年每一次 GPU 调度，也未声称所有存档数值差异均已得到逐值反演。

## 全量冻结 J1 的决策影响

使用全部 288 个 R12 状态、6,809 个候选。归一化直接从完整拟合 checkpoint 读取，没有重新拟合；三 seed 权重、E0 推理、ensemble、校准器和 gate 均不变。组批辅助函数只读取图、目标成员及源特征，不读取标签字段，并通过与原组批路径的输入/输出一致性测试。

每个状态比较存档源特征下的 E0 决策与两种诊断前处理结果。J1 始终为 FP32、确定性算法；前处理分别使用默认或确定性算法。这是影响分析，**不是实现选择或正式资格测试**。

| 与存档输入参考相比的差异状态数 | 默认前处理 | 确定性前处理（仅诊断） |
| --- | ---: | ---: |
| 候选身份/生成顺序 | 0 | 0 |
| 冻结分数数值 | 73 | 114 |
| 派生源特征 | 2 | 2 |
| 支持掩码 | 0 | 0 |
| 神经首选 | 0 | 0 |
| 最终所选动作 | 0 | 0 |
| 回退候选 | 0 | 0 |
| 干预/回退决策 | 0 | 0 |

两种诊断均有 100 个干预状态，最终动作一致率均为 288/288。由于输入特征变化，三 seed 输出最大绝对差可达 0.0077123；不能将它冒充为通过 `1e-5` 的运行时数值等价。一次全量决策一致也不保证所有未来随机归约执行都一致。

影响分析的环境还为 J1 确定性推理设置了 `CUBLAS_WORKSPACE_CONFIG=:4096:8`；因此这组“默认前处理”表示默认归约算法处于统一诊断环境，不能将其 73 个分数差异与此前原始采集环境中的 70 个差异解释为受控改善或恶化。原始采集环境复核证据继续独立保留。

## 待用户确认的具体协议修订

建议保留历史前处理的代码、dtype、排序及输出 cast，**不将其改为确定性前处理**。运行时实现等价改为：同次原路径生成同一份输入，再分别传给 E0 和优化实现，比较全部三 seed 输出、支持掩码、神经首选、回退候选及最终动作；仍要求 eager 尽可能逐位一致，向量化/编译满足原 `1e-5` 误差界，决策 100% 一致。

存档逐值复现差异独立保留并明确披露，不再用反复尝试直到匹配存档的方式判定通过。完整 live 延迟仍必须包括原前处理，不能将缓存输入替换进去；J1 和所有新增优化仍禁止 FP16/BF16。

这项建议改变了用户此前“逐值匹配某次历史存档”的硬要求，**尚未获准执行**。在明确答复前，完整 Phase 6K 晋级保持 HOLD，R13/R14 继续锁定。保留原要求也是有效选择，但原路径的不确定性意味着不能保证逐值复现旧样本。
